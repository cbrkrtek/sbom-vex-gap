Written BEFORE any VEX run. Status of every prediction: UNTESTED.
Grype 0.121.0, DB built 2026-10-28T06:23:30Z (schema v6.1.10), see E1-env.txt.
Target: image built from commit 500158f (app A), one Java CVE chosen from the
base scan.

Origin: I've asked an AI assistant about these:

component_not_present against image contents.

## Predictions and refutation conditions
E1a (false statement, correct identifiers): predict the CVE moves to
  ignoredMatches. Refuted if it stays in matches.
E1b (product only, no subcomponents): no prediction. Record what happens.
E1c (green control: wrong product identifier): predict the CVE stays in
  matches. Refuted if it is suppressed (then matching is looser than assumed).
E1d (signed VEX): predict the same result as E1a. Refuted if the result differs.
E1e (signature broken after signing, cosign verify-blob fails): predict the
  same result as E1a. Refuted if Grype does not apply the file.

## Definitions
- "Suppressed" = the CVE is in ignoredMatches with VEX in appliedIgnoreRules.
- "Not found" = the CVE is in neither array.
- The two are kept in separate rows of the results table.
